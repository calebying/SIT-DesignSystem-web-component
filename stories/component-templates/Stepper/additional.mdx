## Using Sit-step Child Components (Recommended)

The preferred way to use `Sit-stepper` is by composing it with `<sit-step>` child components. This approach provides better flexibility and is the recommended pattern going forward.

```tsx
export interface SitStepProperties {
  stepHeader: string; // The header text for the step
  iconName?: string; // Optional icon name from Sit icon set
  component?: unknown; // Optional component reference for this step
  disabled?: boolean; // Whether this step is disabled
  completed?: boolean; // Whether this step is marked as completed
}
```

## Using the Deprecated Steps Property

The `steps` property approach is now deprecated in favor of `Sit-step` child components. However, it remains supported for backwards compatibility.

> **Note:** The legacy `IStepMetaData` (`steps` prop) approach does **not** support newer `Sit-step` capabilities such as slot-based step descriptions/content and related slot interaction patterns. Use `<sit-step>` children for all new implementations.

## Pass IStepsMetadata to steps prop

`steps` prop is an array of object defined by interface `IStepMetaData`

```tsx
export interface IStepMetaData {
  component: unknown;
  stepHeader: string;
}
```

- `component` refers to the component to render for each step. The type of component set to unknown as it depends on which frontend library you are using.
  For example, it could be a vue component / react component / angular component depending on your frontend library of choice
- `stepHeader` refers to the header title per step.
- The step number is defined by the object's index of the array

## Slotted clickable items

When a clickable `Sit-step` contains interactive elements in its slot (e.g. links or buttons), clicks on those elements
would normally bubble up and also trigger the step's navigation. To prevent this, add the `data-clickable` attribute to
any slotted element whose click should be handled independently and **not** propagate to the step.

```html
<sit-stepper activeStep="1" clickable>
  <sit-step stepHeader="Personal Details">
    <!-- This link handles its own click; the step will not receive the event -->
    <a href="/details" data-clickable>Learn more</a>
  </sit-step>
  <sit-step stepHeader="Address">
    <!-- This button fires its own handler without navigating the stepper -->
    <button data-clickable>Action</button>
  </sit-step>
</sit-stepper>
```

## Stepper in a form context

The example below is build with Lit library. As each frontend library has their own lifecycle hooks and unique syntax for props and event handling,
you will need to manage the rendering of components on your end. Here is a general guide to building a form stepper like the one below.
Reference the API table and methods table carefully when creating the Stepper component.

1. Build your child components. The stepper example has three steps and each step has its own component.
   These three components will be the direct child of your StepperComponent :

- Step 1: Personal Details
- Step 2: Address and Contact details
- Step 3: Review

2. Create the parent component. This is where all the state of `steps` and `activeStep` will be managed and should persist.
   This component should capture and store any user input. This component should handle the dynamic rendering of child components depending on the current `activeStep`.
   Use SitStepper's `getComponent` public method to obtain current component.
   Make use of the SitStepper's public methods to create button actions for next/previous/last/first step or reset.
